🧠 13. Aprendizado da IA com Tickets Resolvidos NOVO

Conceito: A IA aprende com tickets resolvidos anteriormente para sugerir solucoes melhores e mais rapidas. Quando um ticket e fechado, o sistema extrai a conversa, gera um resumo estruturado via Claude e indexa para consulta futura.

Como Funciona

1
Ticket e fechado com resolucao
2
index_resolved_ticket() extrai conversa completa (ate 50 mensagens)
3
Claude gera resumo estruturado: CATEGORIA, PROBLEMA, SOLUCAO, TAGS, RESUMO_IA
4
Resolucao salva em ticket_resolutions com pontuacao de satisfacao
5
Em mensagens futuras, find_similar_resolutions() busca resolucoes parecidas
6
Resolucoes similares sao incluidas no contexto do Claude para gerar respostas melhores

🎤 14. Transcricao de Audio do WhatsApp NOVO

Fluxo:
  • Mensagem de audio recebida (type=audio, mime: audio/ogg)
  • Download do audio via Media Service (download_media())
  • Audio convertido para base64 e enviado ao Claude API para transcricao
  • Texto transcrito salvo no campo content da Message
  • message_type atualizado para audio_transcribed
  • Texto transcrito usado como input para classificacao de intent e geracao de resposta

Service: transcription_service.py

transcribe_audio(audio_bytes: bytes, mime_type: str) -> str
  • Converte audio para base64
  • Envia ao Claude como mensagem multimodal (content type: audio)
  • Prompt: "Transcreva o audio a seguir para texto em portugues"
  • Retorna texto transcrito
  • Fallback: "[Audio recebido - transcricao indisponivel]" em caso de erro

Service: media_service.py

  • get_media_url(media_id, token) → URL temporario da Graph API
  • download_media(media_id, token) → bytes do arquivo
  • upload_to_storage(file_bytes, filename, content_type) → salva localmente com hash
  • Tipos suportados: jpg, png, webp, pdf, ogg, mp3, mp4

Calculo de ROI

  • Custo IA mensal: interacoes_bot x tokens_medios x custo_por_token
  • Custo humano mensal: atendentes_necessarios x salario_mensal
  • Custo hipotetico (sem IA): total_interacoes / capacidade_humana x salario
  • Economia: custo_hipotetico - (custo_IA + custo_humano)
  • % Economia: economia / custo_hipotetico x 100
  • Tempo economizado: tempo_medio_humano - tempo_medio_IA

👤 17. Autocadastro de Aluno pelo WhatsApp NOVO

Conceito: Alunos podem se cadastrar diretamente pelo WhatsApp, sem precisar ir ao campus. O bot coleta informacoes step-by-step e cria o registro preliminar no sistema.

Fluxo de Autocadastro

1
Aluno envia primeira mensagem e escolhe "desejo me inscrever"
2
Bot coleta: Nome completo
3
Bot coleta: CPF (validacao de formato e digitos verificadores)
4
Bot coleta: E-mail (validacao de formato)
5
Bot coleta: Curso desejado
6
Bot exibe resumo e pede confirmacao
7
Cria registro em students com status pending_enrollment
8
Gera RA automatico e vincula ao Contact

🚨 19. Dead Letter Queue

Quando process_incoming_message falha 3 vezes:
  • on_failure handler persiste FailedTask no banco
  • Campos: task_id, task_name, args, error_message, traceback, retry_count
  • Admin pode re-enfileirar via API
GET /api/v1/admin/failed-tasks → super_admin only
POST /api/v1/admin/failed-tasks/{id}/retry → re-enfileira mensagem

🔗 20. Webhooks de Saida (Integracao ERP)

  • Tenants cadastram endpoints para receber eventos
  • Eventos: conversation.closed, ticket.created, * (todos)
  • Payload assinado com HMAC-SHA256 (header X-IGS-Signature)
  • Retry exponencial: 1, 2, 4, 8, 16 minutos (ate 5 tentativas)
  • Registro de cada delivery: status_code, response_body, success
GET /api/v1/webhooks → listar endpoints
POST /api/v1/webhooks → cadastrar endpoint
PATCH /api/v1/webhooks/{id} → atualizar
DELETE /api/v1/webhooks/{id} → remover
GET /api/v1/webhooks/{id}/deliveries → historico de entregas
