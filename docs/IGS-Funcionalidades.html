📱 12. Fluxo de Mensagens WhatsApp

Fluxo Completo (Backend)

1
Usuario envia mensagem no WhatsApp
2
Meta Cloud API → POST /api/v1/webhook/whatsapp (verifica HMAC-SHA256)
3
Cria/encontra Contact → Cria/encontra Conversation → Salva Message
4
Enfileira task Celery process_incoming_message
5
Se contato nao verificado → pede RA/matricula, retorna
6
Classifica intent via Claude (~50 tokens): grade_query, boleto_query, payslip_query, etc.
7
Se human_handoff → cria Ticket + status waiting_agent
8
Carrega dados do BD conforme intent (notas, boletos, holerites, etc.)
9
Busca artigos KB relevantes (ILIKE full-text)
10
Gera resposta via Claude com RAG (~200-500 tokens)
11
Envia resposta via WhatsApp Cloud API
12
Salva Message (sender_type: bot) + atualiza metricas Prometheus
13
Broadcast via Redis pub/sub → WebSocket → painel em tempo real

🚨 13. Dead Letter Queue

Quando process_incoming_message falha 3 vezes:
  • on_failure handler persiste FailedTask no banco
  • Campos: task_id, task_name, args, error_message, traceback, retry_count
  • Admin pode re-enfileirar via API
GET /api/v1/admin/failed-tasks → super_admin only
POST /api/v1/admin/failed-tasks/{id}/retry → re-enfileira mensagem

🔗 14. Webhooks de Saida (Integracao ERP)

  • Tenants cadastram endpoints para receber eventos
  • Eventos: conversation.closed, ticket.created, * (todos)
  • Payload assinado com HMAC-SHA256 (header X-IGS-Signature)
  • Retry exponencial: 1, 2, 4, 8, 16 minutos (ate 5 tentativas)
  • Registro de cada delivery: status_code, response_body, success
GET /api/v1/webhooks → listar endpoints
POST /api/v1/webhooks → cadastrar endpoint
PATCH /api/v1/webhooks/{id} → atualizar
DELETE /api/v1/webhooks/{id} → remover
GET /api/v1/webhooks/{id}/deliveries → historico de entregas
